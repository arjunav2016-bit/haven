Chapter 3 : OOP Foundations

The Four Pillars of OOP in HAVEN

Concrete codebase anchors demonstrating core object-oriented principles
Slide 07 / 16
🔒
1. Encapsulation
  • All fields in Accommodation and User are strictly private.
  • Setters enforce domain invariants: baseRent > 0 and vacancies >= 0, throwing IllegalArgumentException.
  • Defensive copying on getters: returns new ArrayList<>(amenities) to prevent external array mutation.
🧩
2. Abstraction
  • Generic repository interface Repository<T, ID> shields views from data storage details.
  • Abstract base class Accommodation declares the abstract contract calculateTotalMonthlyCost().
  • ReportGenerator enforces a fixed algorithm skeleton while abstracting body formatting.
🌳
3. Inheritance
  • Hostel (mess fee, curfew) and PG (utilities, food) extend Accommodation.
  • Student, Owner, and Admin inherit common auth fields from User.
  • AccommodationDecorator inherits from Accommodation to wrap stays seamlessly.
⚡
4. Polymorphism
  • Dynamic method dispatch on calculateTotalMonthlyCost(int sharing) resolved at runtime.
  • Hostel adds fixedMessFee; PG adds utilityCharges; Decorator applies percentage discount.
  • Polymorphic repository switching via RepositoryFactory implementations.

Chapter 3 : System Workflow

End-to-End Operational Lifecycle

Transactional sequence from property discovery to booking confirmation
Slide 09 / 16
📋
5-Stage Transaction Flow
  • Step 1: Multi-Filter Search — Student filters by rent, distance from SCTCE, and curfew; results update via debounced iterator.
  • Step 2: Embedded Map Inspection — Student inspects property on MapPanel, verifying coordinates and proximity.
  • Step 3: Atomic Vacancy Decrement — HostelDAO.decrementVacancy() reserves a spot atomically. If zero, throws VacancyExhaustedException.
  • Step 4: Warden Confirmation — Owner inspects enquiry, transitions state from PENDING $\rightarrow$ CONFIRMED.
  • Step 5: Timestamped Receipt — Student downloads standardized booking slip generated via BookingReceiptReport.
🔄
Enquiry State Machine (State Pattern) 
       [NEW BOOKING SUBMISSION]
                  │
                  ▼
         ┌──────────────────┐
         │   PENDING STATE  │ ──► [CONTACTED STATE]
         └──────────────────┘            │
                  │                      ▼
                  │             ┌──────────────────┐
                  ▼             │ CONFIRMED STATE  │
         ┌──────────────────┐   └──────────────────┘
         │  DECLINED STATE* │            ▲
         └──────────────────┘            │ (ILLEGAL TRANSITION)
                  ▲                      │
                  │                      │
         ┌──────────────────┐            │
         │ CANCELLED STATE* │ ───────────┘ Throws IllegalStateException

Chapter 4 : Implementation

Critical Code Snippets

Demonstrating clean OOP implementation across core services
Slide 11 / 16
A. Subtype Polymorphic Costing 
// In Hostel.java
@Override
public double calculateTotalMonthlyCost(int sharing) {
    double disc = (sharing >= 2) ? 500.0 : 0.0;
    return (getBaseRent() - disc) + fixedMessFee;
}

// In PG.java
@Override
public double calculateTotalMonthlyCost(int sharing) {
    double disc = (sharing >= 2) ? 400.0 : 0.0;
    double food = isFoodIncluded() ? 2000.0 : 0.0;
    return (getBaseRent() - disc) + utilityCharges + food;
}
B. State Pattern Terminal Guard 
// In CancelledState.java
public class CancelledState implements EnquiryState {
    @Override
    public void confirm(Enquiry context) {
        throw new IllegalStateException(
            "Cannot confirm an enquiry that has been CANCELLED."
        );
    }

    @Override
    public boolean isTerminal() {
        return true;
    }
}
C. Reversible Command Execution 
// In AdminDashboardPanel.java
private void executeCommand(AdminCommand cmd) {
    cmd.execute();
    commandHistory.push(cmd);
    updateUndoRedoButtons();
    refreshAdminData();
}

// In CommandHistory.java
public void undo() {
    if (!undoStack.isEmpty()) {
        AdminCommand cmd = undoStack.pop();
        cmd.undo();
        redoStack.push(cmd);
    }
}
Chapter 4 : Implementation

Challenges Encountered & Engineering Solutions

Critical bugs and architectural blockers resolved prior to oral examination
Slide 12 / 16
Technical Challenge Root Cause Analysis Engineering Solution Implemented
Offline Map Tile Loading Hang OSM tile servers block requests lacking custom User-Agent; background threads stall indefinitely on campus firewalls. Configured custom User-Agent in MapPanel, implemented FileBasedLocalCache in data/cache/tiles, and wrapped in fallback to EmptyTileFactory.
MongoDB 30-Second Timeout Freeze Default driver waits 30 seconds before throwing timeout when MongoDB is offline on localhost during demos. Configured serverSelectionTimeout(2000) and socket connectTimeout(2000) in MongoDBConnection, prompting offline store mode in < 2s.
EDT Image Loading Lag & NullPointer Synchronous disk reads via ImageIO.read() on Swing Event Dispatch Thread caused list scrolling lag. Implemented thread-safe ConcurrentHashMap icon cache in PropertyImageStorage; rendered styled fallback JPanel ("No Image Available") if missing.
Subtype Polymorphic Deserialization MongoDB BSON vs JSON numbers caused ClassCastException on utilityCharges / fixedMessFee. Built defensive getDoubleSafe() helper in FilePersistenceManager and MongoAccommodationRepository.
Live Viva Demonstration of Exception All properties had vacancies > 0, making it impossible to trigger VacancyExhaustedException in 1 click. Configured BH04 (Castello Boys Hostel) to vacancies: 1 in haven_store.json so 1 click drops it to 0, and the next click triggers the exception live.
